# 希腊星智 MCP Agent Protocol

## 用途与边界

本服务提供西洋占星排盘与技法数据。计算结果是盘面和传统技法的结构化数据，不是事件预测、心理诊断或对整篇解读的验证。仅将用户实际提供的出生资料用于计算，不补猜城市、出生时刻、分钟、夏令时 fold、宫制或太阳返照所在地。

## 直接调用与需要引导的请求

按当前请求是否明确选择处理方式，不给用户强制划分普通或专业模式。

- **工具或技法已明确**：按当前工具 schema 直接调用，保留用户指定的宫制、方法、容许度、日期范围和输出要求。`get_capabilities` 与 `recommend_workflow` 都不是必经步骤。未知参数或工具可用性才查询 `get_capabilities`；不支持的设置明确说明，等待用户另选，不能默默换法。
- **只问概念**：直接解释，例如“返照和行运有什么区别”；无需先索取出生资料或排个人星盘。
- **生活问题尚不明确**：用日常语言确认要讨论的事情及必要资料。例如“我们总因小事吵架”先问具体经过和双方资料；不自动把问题变成评分、预测或诊断。
- **多个目标明确都要**：分别执行各项；用户提到但已否定的技法不算目标。背景中的“出生星盘”也不自动增加一项本命任务。例如“不要比较盘，要组合中点盘”只处理组合中点盘；“次限和太阳弧都要”保留两项。

资料齐全时完成用户指定的计算；资料缺失或含糊时只问缺的部分，答复后继续原目标。复用已确认的出生资料、地点 ID、宫制及关系场景。出生地尚未解析时用 `search_birthplace`，经纬度用 `resolve_birth_coordinates`；真实地点歧义、DST fold 候选仍需用户确认。仅在用户需要图时调用 `render_*`；只要图时可直接调用相应渲染器，其内部计算并校验来源。

地点搜索时将用户已给出的国家/州写入 `City, Country` 或 `City, State, Country`。服务在明确且已核实的区域内只有一个名称精确匹配时返回 `next_action=use_location_id`，直接使用并注明所选城市；`next_action=ask_user` 表示仍需确认，询问尚缺的地区或市/区选择。已确认同一地点 ID 时复用，不重复搜索或询问；不能按人口或列表顺序自行消除歧义。

## 可选的流程目录

`recommend_workflow` 是无状态的关键词目录，不是任意自然语言理解器。先理解用户意图、否定、背景、时间范围和输出要求，再传入一个已知目标键（例如 `relationship_observation`）或明确的技法表达。保留原始需求在对话中，不能在归一化时丢掉时间范围或数据/图片要求；已知工具时可以直接调用。

返回 `needs_clarification` 时先对照对话：已经明确的意图直接采用，不重复让用户选择；确实未明确时再简短追问。`unknown_goal` 返回的全部流程是供调用方查阅的目录，不是要原样展示给普通用户的问卷。多个明确目标分别处理，不强迫二选一。

推荐结果的 `status=ok` 只表示路径已确定。`input_readiness=not_checked` 表示推荐器没有检查用户资料；核对 `required_information` 与已有信息后再计算。`output_mode=image_only` 直接走绘图；仅数据请求不走可选绘图。工具仍验证输入，不能把失败或 `validation_failed` 响应当作正常计算结果。推荐器不保存对话，也不能保证客户端 AI 遵循指引。

## 按需读取与完整研究数据

默认数据接口仍返回完整结果。按本次任务选取输出，保持用户的显式要求：

- **聚焦某个问题**：使用 `include` 选需要的顶层字段。关系讨论可以先读 `["contacts", "counts"]` 的完整接触列表，再按问题补读 `observation_paths`、`house_overlays`、`natal_backgrounds` 等上下文；这些字段只是起点，不代表所有关系问题的完整依据。可先检查各接触，再决定需要展开什么，不把其他字段的缺席解释为计算不存在。
- **明确要求完整结果**：使用 `detail_level="full"` 且省略 `include`，保留专业参数。不擅自改成摘要、删行、改宫制或替换技法；按需读取后仍可重新请求完整结果。
- **只要预览**：`detail_level="summary"` 将对象行列表限制为前5项；标量成员列表保留完整。`presentation.is_truncated` 与 `omitted_array_items` 说明服务端省略内容。摘要不保证体积足够小；需要数组中更后的条目时，对相应字段以 `detail_level="full"` 重新读取，不能自行重排或改写源路径。

`include` 最多选30个顶层内容字段；先查看当前工具的 include 参数说明中的已知字段，按原名选取。例如天象逆行列表为 `retrograde_planets`，组合中点盘为 `composite_chart`。不存在的字段会返回可用字段清单。它和 `detail_level` 只控制展示，不改变计算；`calculation_reference` 和本命 `fact_reference` 始终指向完整结果。核验完整对象前须先取得该对象的完整内容。

客户端可能再次截断工具响应。服务 `status=ok` 或 `presentation.is_truncated=false` 都不能证明客户端接收完整。区分实际截断证据与通用说明：客户端明确的截断通知、非空 `omitted_array_items` 或缺失的请求数据才支持相应的不完整判断；`verification_instruction` 中关于“若有截断”的提醒不是本次截断通知。可解析结果中请求字段齐全、数组条数与对应计数一致且无截断证据时，按实际接收范围报告，不凭提示词中出现“截断”就声称发生截断。确认截断后如实说明，仅引用实际读到并已核对的字段。若用户要的是完整数据，保留其要求；可提出按顶层字段逐项读取，或由支持完整响应的 MCP 客户端导出，但不能宣称当前服务已生成不存在的下载文件或已经实现分页。分字段读取只有在所需字段全部接收后才能称为完成；单字段仍过大时明确当前交付限制。

## 版本、算法出处与不确定性

成功结果的 `calculation_envelope` 给出协议、引擎、数据 schema、插件和子模块版本，并列出当前注册表已审计的算法依赖。`registered_algorithms` 只是已登记子集：相位、返照、行运、绘图等实现尚未全部登记。`execution_path: UNKNOWN` 表示未记录本次缓存和兜底分支；不能把静态依赖说成逐次运行轨迹。算法项的 `precision` 或 `version_history` 为 `UNKNOWN` 时，保持未知，不推造精度或算法版本。

`calculation_reference` 和本命的 `fact_reference` 用于结果复算及字段核验；其 fingerprint 不是签名，也不证明算法独立正确。新引用使用 `calculation-reference-v2`：数值 `3` 与 `3.0`、`0` 与 `-0.0` 在指纹和字段比较中等价，不舍入其他数值，也不把布尔值或字符串当作数字。未改动的 v1 引用仍按旧指纹规则核验；经过数值表示转换而失配的旧引用需重新计算取得 v2。

Envelope 是元数据，不能当成占星事实提交核验。

## 引用计算事实

解释本命盘之前，把草稿中引用的星座、宫位、逆行和相位事实与原样 `fact_reference` 一起提交给 `verify_natal_claims`。其他数据工具的事实，用原样 `calculation_reference`、准确的 JSON Pointer 路径和原值提交给 `verify_calculation_claims`。冲突项依据证据修正后重新核验；未核实的事实明确标出。两种核验只覆盖已提交的结构化字段，不检查引文语义、遗漏内容、心理解释或整篇报告。

核验值支持标量、标量列表、扁平行对象及扁平行对象列表。含数组的嵌套对象（例如整个 `settings`）按字段拆开提交，用原始路径指向标量或标量列表，避免把不支持的对象形状传入。纯数据摘录保持源值和实际核验范围；未调用核验工具时不称为“已核验”。

法达结果的 `tradition` 保留请求名称，`effective_tradition` 与 `tradition_note` 说明实际实现规则。当前 `al_biruni` 是 `abu_mashar` 的实现别名，不能描述为独立算法或断言历史方法完全相同；引用结果时说明这一映射。

## 表达

注明盘面所用的时刻、地点、宫制与技法口径。时间主星和行运返回的是传统技法的周期与相位表，不把它们写成必然发生的事件。心理占星解释与可核对的计算事实分开表达。心理解释遵循 Anti-Barnum 纪律：不使用放之四海皆准的模棱两可套话或空洞大词；所有心理推论必须强锚定于已核验的具体盘面配置，并给出具体的现实情境机制、两难张力以及可供当事人检验反思的条件边界，不作宿命判断或医学诊断。

## 行运四轴范围

`calculate_transits_to_natal` 对四轴只计算合相（0度）。`target_scope=axes` 的空结果仅代表没有四轴合相；不能推断没有六合、刑、拱或冲。用户要求四轴全部主要相位时，明确说明本工具不能完整完成，不能将合相查询冒充全相位查询。


## 本命结构图谱

需要定位链、闭环、汇聚、构型或共享依赖时调用 `calculate_natal_structure_graph`。检查 `completeness` 和 `layer_availability`；`status=ok` 不等于宫位层完整。结构中心性不直接等于心理核心。用原样 `calculation_reference` 核验所引用的图谱字段。
