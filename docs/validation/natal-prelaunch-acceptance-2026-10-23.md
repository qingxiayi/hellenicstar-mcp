## 验收范围与结论

本轮验收 `relationship_views` 接入后的计算事实、候选方向、完整状态和本地 MCP 交付。结论：在本次覆盖范围内未发现需继续收窄候选或修改算法的问题，可以进入发布准备。该结论不代表公网服务已有新字段，也不代表恢复了报告作者的“药”筛选公式。

代码与此前[逐文件源码指纹](natal-relationship-views-v1-fingerprint.json)逐项匹配，没有算法改动。本轮只更新功能说明与验收材料。旧测试记录不作为本轮重跑结果。

## 本轮实际运行

- `UV_CACHE_DIR=/tmp/natal-acceptance-uv-cache PYTHONDONTWRITEBYTECODE=1 bash scripts/verify.sh`：65 个依赖包一致性检查通过；**981 passed**，52.40 秒；仅原有 Kerykeion `datetime.utcnow` 弃用警告。
- 三份经用户授权的出生盘重新计算并通过完整输出验证；真实本地 stdio MCP 逐盘调用 `calculate_natal_salience`，显式请求 `relationship_views` 与 `core_structures`，返回 `status=ok`、`quality.status=passed`。
- MCP 工具发现中的默认 `orb_view` 为 6，说明包含新字段；返回层内双方状态引用均可解析。每盘真实依赖清单声明获 `supported`，故意错误声明获 `contradicted`。
- 新随机种子 `2026102309` 的 `held_out(..., 24)` 加一张极地样本，共 25 张，检查结果集合保全、不同目的清单可重叠但与背景不重叠、自身不作外部对象、极地未知宫位不伪造；未出现失败。
- 这些样本的终端组包括 32 个自定位、5 个双节点环、8 个多节点环；多个终端可在同一盘并存，数字为组数而非盘数。例如 `holdout-004` 同时有木火土三节点环及水星、太阳自定位，`holdout-016` 有木火水土四节点环及金星自定位。没有强行生成唯一终端。
- 极地样本：2000-06-21 12:00，`coord:78.223200,15.646900`；结果明确为部分数据，仍可计算关系，宫位保持未知。

上一轮重跑的 152 张固定样本及 1,520 份视图结果见[查看层验收](natal-relationship-views-v1.md)。本轮没有为增加数量重复运行该同一批样本。

## 私有报告核对

出生数据、原报告、完整结果与逐星对照只保存在本地临时文件，不加入开源仓库。核对覆盖报告第 1–3 章的结构与状态事实，以及第 5 章候选关联；第 4 章时间推演和心理／生活建议不属于本次本命查看层验收。

| 类型 | 本轮结论 |
|---|---|
| 终端、入口、直接／间接汇入 | 结构事实与报告一致，按七星口径核验 |
| 半球、象限、元素、模式 | 使用报告所述点集核验一致；元素／模式含 ASC、MC，半球／象限只统计十星 |
| 七颗古典行星两制落宫、定位链、关键宫主关系 | 已核对，无新遗漏 |
| 两组无主要相位的互容 | 保留互容及双方方向，不伪造成相或有效资源 |
| 报告第 5 章明确点名的候选关联 | 17 条均可从新查看层追溯；这是关联覆盖，不是“药”的效果或优先顺序复现 |
| 报告明确列出且在 6° 内的行星相位数值 | 14 条的类型及 orb 四舍五入到两位小数一致 |
| 较宽相位及依赖它的构型 | 按用户选定的 ≤6° 门槛排除，属于主动口径差异 |
| 三分尊贵 | 主星身份、昼夜角色、当值计入、3/2/1 对照分别披露；报告未给精确计分公式，不认定已经复刻 |
| 失势／落陷 | 程序保留 detriment 与 fall 的区别，不因报告中文泛称而合并 |
| 轴点数值 | 关系存在，但有小数差异；报告缺精确坐标，原因未能唯一确定。不靠修改时间或坐标强行拟合 |
| 最好用、药、必须先后处理 | 保持未判定，不将作者解释混入确定计算 |
