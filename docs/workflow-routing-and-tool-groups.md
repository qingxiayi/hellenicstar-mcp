# 工作流推荐与工具分组评估

本轮仅修复 `recommend_workflow` 的任务选择，不删除、隐藏或合并工具，不改变计算接口。保留全部 48 个工具。本文的分组是后续方案，尚未启用。

## 已修复的选用问题

| 用户请求 | 推荐路径 |
| --- | --- |
| 画今日天象盘 | `calculate_sky_chart`；需要图片时 `render_sky_chart`；确认观测地点，不要求出生资料 |
| 看现在的行运双盘 | `get_transit_snapshot`；需要图片时 `render_transit_biwheel`；使用 moment，不要求区间起止日期 |
| 次限月相 | `calculate_progressed_lunation` |
| 琼斯格局图 | `calculate_classical_factors`；需要图片时 `render_jones_pattern` |
| 黄道释放 L4 | 先取得 L3，再确认 lot、parent_start、parent_sign，调用 `calculate_zodiacal_releasing_l4` |
| 关系观察 | `calculate_relationship_observation`；确认模式、所需出生资料与关系场景 |

同时补充组合中点盘、宫主定位链、当前相位窗口、生涯行运和土木进宫的路由，以及已有返照、次限、太阳弧、戴维森、迁居、本命流程的可选出图步骤。比较盘不自动改画组合中点盘。

只有明确登记的同一技法专称可以覆盖其内部泛称，不再按匹配长度任意淘汰另一技法。例如 `sky chart` 中的 `sky` 不再产生两个候选；`sky chart and current sky` 仍返回两个候选供选择。既有工作流键继续有效。

“画本命盘和天象”等并列需求保留全部候选；“今天的行运到年底有哪些精确日期”选区间查询；明确同时要求快照与精确日期时保留两种路径，不能互相替代。

出图步骤仅在用户要求图片时执行。数据流程不会因可选绘图工具缺失而失败；明确要图时才检查绘图工具是否可用，没有对应图种时返回澄清而不擅自替换。仅要图片可以直接调用渲染工具，其内部已有来源计算与校验；不必为画图重复调用数据工具。需要结构化字段或解读时使用计算与核验步骤。已确认的地点无需重新搜索。仅图片流程的 `first_calculation_tool` 指向内部带计算的绘图工具；琼斯图片不再要求古典数据工具的宫制参数，太阳弧图片提示单个绘图年龄。

这仍是确定性关键词路由，不是任意自然语言理解器。没有匹配或出现多种技法时返回澄清选项；不能把测试样例通过当作所有表达都能识别。否定、复杂省略和跨句指代仍由调用方结合用户上下文判断。推荐流程也不证明用户已提供或确认了出生时间、关系场景等参数。

## 用户补充资料与 AI 调用的分工

`recommend_workflow` 是无状态的流程建议器，不是自动执行全部步骤的对话机器人。它只接收目标，不接收或保存出生资料，因此 `status=ok` 只表示找到路径。

- 目标不明或混合：返回候选、`question` 和 `next_action=ask_user`。调用方结合对话澄清；用户已明确全部都要时分别处理，不强迫只选一个。
- 路径明确：返回 `next_action=check_required_information` 和 `input_readiness=not_checked`。AI 对照已有对话，只询问缺失或含糊的必需项；已确认资料复用。
- 用户回答：AI 将已确认信息传入对应工具。计算工具仍检查缺失、类型及业务约束；不能把路由成功视作参数验证通过。
- `output_mode` 为 `data` 时无绘图步骤；`image_only` 直接走绘图；`data_and_image` 提供数据与图；`unspecified` 保留计算路径及当前可用的可选绘图步骤。

协议同时通过工具、resource 和 prompt 提供。不同客户端是否读取并遵循协议需要另行实测；代码测试不能证明所有模型都会正确追问，参数检查也不能识别模型编造但格式合法的资料。

## 分组建议：先做客户端展示，不删服务端能力

| 场景 | 主要工具族 | 需随组提供的基础能力 |
| --- | --- | --- |
| 日常天象 | 当前天象、指定地点天象盘、相位窗口、行星相位扫描 | 地点解析、通用核验、协议与发现 |
| 本命研究 | 本命盘、古典要素、特殊点、宫主、结构图谱、本命重点、琼斯图 | 地点解析、本命及通用核验、协议与发现 |
| 推运与周期 | 行运、次限、太阳弧、返照、时间主星、黄道释放、土木周期及对应图表 | 地点解析、通用核验、协议与发现 |
| 关系咨询 | 比较与组合盘、戴维森、关系观察、人工笔记 | 双方地点解析、通用核验、协议与发现；明确人工陈述非计算事实 |

分组可以重叠。保留完整专业模式，不能仅凭未进入某组就删除算法。资源和提示词兼容性要按客户端实测；`get_agent_protocol` 目前仍作为工具保留。

不建议现在把 12 个绘图接口改为单个万能入口：虽然入口数会减少，但出生资料、目标日期、地点和图种的条件参数会更复杂，需要验证实际任务成功率才决定。两个核验工具也不能直接互换输入；若未来统一，应保留语义型和字段路径型两种契约及旧接口过渡。

## 启用分组前的验证条件

- 对固定的中文和英文任务，比较正确选用率、无用调用次数、澄清是否必要与最终输出是否满足任务。
- 覆盖仅图片、仅数据、多技法请求、未提供出生时间、无对应绘图功能、L4 父周期待选、旧客户端调用。
- 每个分组必须包含核验与地点解析依赖；分组内建议不能指向不可用工具。
- 先在一个明确的客户端试用显示分组，再决定是否需要独立的服务器配置。当前没有实现动态工具发现、切换分组或隐藏入口。
- 没有完整用户调用统计或分组对照实验，不声称某工具没人用，不承诺减少入口会提高 Glama 分数。
