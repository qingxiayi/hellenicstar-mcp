# 本命重点提取

独立工具 `calculate_natal_salience` 消费完整本命结构图谱，按明确规则提取候选并提供完整画像。它不另算星历，不替换 `calculate_natal_structure_graph`，不处理关系盘。

本版规则和输出独立版本化为 `natal-priorities-v1`。**没有总分、前三名目标、吉凶评分或唯一心理核心。** 报告提供筛选原则，不被当作某个未知精确公式的证明。

## 调用与配置

```json
{
  "year": 2000, "month": 1, "day": 1, "hour": 12, "minute": 0,
  "location_id": "coord:39.904200,116.407400",
  "scope": "classical7",
  "rulership": "traditional",
  "orb_view": 8,
  "tight_orb": 3,
  "axis_orb": 5,
  "include_mc_ruler": false,
  "distribution_points": "ten_plus_asc_mc",
  "reception_policy": "dignity_only",
  "dynamics_days": 30
}
```

- `scope`：参与汇入统计的起点为 `classical7` 或 `ten`。它不删除完整图里的中间节点，不限制相位与构型只用七星。
- `rulership`：`traditional` 或 `modern`。现代规则为天海冥替代守护，不是共同守护。七星起点也可以用现代守护，中间节点及终端可能涉及外行星。
- `orb_view`：原图谱已有6、8、10度视图。上游未识别的相位不会通过加宽筛选恢复。
- `tight_orb`：触发相位入选的门槛，默认3度，允许0至所选视图上限。**入选行星画像保留整个视图内的相关相位**。
- `axis_orb`：真实轴点黄经接触门槛，默认5度，允许0至10度，支持0/60/90/120/180度。
- `include_mc_ruler`：是否增加MC守护星身份入口，默认关闭。
- `distribution_points`：元素/模式选择 `ten` 或 `ten_plus_asc_mc`，默认后者；宫位分组始终统计十星并明确点集。

- `reception_policy`：`dignity_only`／`sign_aspect`／`degree_aspect`／`applying_degree_aspect`，默认第一项。只改变条件检验，不删事实或改定位核心。
- `dynamics_days`：从出生时刻向后查找的天数，整数1–90，默认30；不是行运解释窗口。

未知配置、非法阈值、缺少必需出生信息以及有歧义的民用时刻都不会被静默补值。没有权重参数。

## 终端和外部入口

终端类型为 `self`、`two_node_cycle`、`multi_node_cycle`。双节点闭环不自动等于所有形式的互容，接纳依据另列。多个终端均保留。

每组记录 `members`、`origins`、`numerator/denominator`、`coverage`、`external_origins`、`feeders.direct/indirect`、`paths`、`first_entry`、`main_entries`、`internal_edges`。

`first_entry` 只统计终端外起点第一次进入哪一名成员，不能把环内来回计作新的输入。主要入口按外部起点数取最大值，允许并列；没有外部输入时为空。直接/间接统计以进入整个终端所需步数定义，终端自身不算外部起点。

## 多入口和完整画像

候选入口依次为：终端成员及主要入口、日月/命主/可选MC主、轴点接触、紧密相位、构型、日月所在宫位的宫主、角宫两颗及以上行星集中。规则类别用于阅读顺序，不代表心理重要性排序。同类行星按稳定标识排序；相位按orb，构型按成员数再按标识。

状态不是入选门槛：落弱、逆行、6/8/12宫关联不会单独自动生成全盘核心。画像保留落座、多项尊贵、逆行、焦伤/东西出、双宫制位置、全部掌管宫位、定位星及其状态、完整路径、所选视图全部相位、接纳/互容、构型角色及轴点接触。外行星无古典尊贵结果时明确标记未定义，不能当作游离。

几何相位只描述几何；不把三分/六合直接定为支持，不把刑冲定为坏结果。接口只做算法，不生成心理假设、行为建议或“病药”综合。

### 三分口径与资源核查

画像新增 `triplicity_context`，复用古典引擎的三分主星表，列出昼主、夜主、参与主和该行星担任的角色。`counted_by_engine` 仍遵守现有昼夜主规则；披露其他角色不改变尊贵分数、游离标记或重点入选。例如昼盘白羊木星具有夜主角色，但这不等于现有规则下的三分尊贵。报告未明确采用哪种口径时，应保留差异，不能认定已经复现其算法。

画像 `resource_review`（策略版本 `structural-candidates-v2`）按对象归并定位星、原有互容、达到引擎尊贵门槛的定向关系、当前相位档内五种主要相位及共同构型。合相、刑冲、六合、三分均只是结构连接；共同构型保留双方角色，并通过 `priority_configurations` 查看包含与共享关系。自身尊贵、运行、宫位、轴点及构型信息另列在 `intrinsic` 中，不需要外部候选才能存在。每条关系保留来源，同一对象同时符合多个条件时保留全部理由，不累计分数。紧密相位入选门槛不会裁剪这里的关系。

每个候选带 `counterpart_state`，包括其尊贵、三分口径、运行状态、两制宫位、掌管宫位、全量相关相位、定位路径和轴点接触。因此，互容没有相位、候选自身落弱／逆行／刑冲、外行星古典尊贵未定义等信息不会被掩盖。定位星为自身时不列作外部资源；没有外部候选只代表未命中所声明的连接规则，不否定自身状态事实。

这套候选规则是本项目明确设计的核查策略，**不是已还原的原报告公式**。`verdict` 固定为 `null`，`assessment` 为 `not_evaluated`，不输出“最佳用药”、有效性、心理或医疗结论。它不参与重点排序，也不改旧图谱。

## 去重与来源

### 分层阅读（`natal-reading-v1`）

这是阅读策略，不改变原候选、星历、尊贵或定位核心。`structural_backbone` 保留所有终端；构型先展示当前档内没有被另一构型包含的对象，随后按 `configuration_expansion` 展开内部构型和共享关系。“最大”指边集合没有被另一构型包含，不表示心理重要性。多个重叠大构型可以同时显示。

`identity_and_local` 保留身份、轴点、紧密相位、构型角色、日月宫主和角宫集中证据；`complete_profiles` 引用原完整画像。`candidate_coverage` 直接披露是否十星全选，不以删资料制造精简效果。

证据矩阵每行对应一颗星，按定位、身份、角宫／轴点、相位、构型、宫主、接纳分列。`usage=selection` 表示该证据触发原规则入选，`context` 表示关联背景。例如终端外的起点可以与终端有关，但不因此冒充终端成员。单元格链接原 `evidence_index`，保留同义与相关组；不声称列与列统计独立。行星状态仍在完整画像内，不作加权票数。

### 针对具体事项的资源核查（`natal-resource-checks-v1`）

先列原事实中的落弱／落陷／游离、逆行、日光状态、6/8/12宫关联及刑冲，作为核查事项。这是明确的传统分类策略，不是疾病、凶险或核心判定。两宫制分别记录；外行星缺古典状态、缺宫位、刑冲另一端未有已入选画像时明确标记覆盖边界。

单星事项引用该星的现有资源候选；刑冲按同一相位合并，并查看两端各自的候选。候选连接两端时标 `all_affected`，只连接一端时标 `some_affected`。刑冲当事星不被列作这组刑冲的第三方候选。引用可查对方完整状态及每条路线；共同连接不自动成为新构型或救应。

**这一层识别的是与事项当事星的结构连接，尚未判定连接是否能处理该事项。** `relevance` 明示未评估解决能力，`verdict=null`；没有候选不等于“无药”。太阳的日光状态为空时视为不适用，不生成虚假日光问题。引用均以完整工具返回值为根；若用 `include` 裁剪返回值，应同时保留引用所需的 `priority_planets`、`core_structures`、`priority_configurations` 和 `evidence_index`。

来源追溯不用于直接判定语义相同。同一黄经可参与落座、宫位和相位计算，这些问题不同。

- 同一身份、相位、构型用稳定标识归并。相同记录重复或输入顺序改变，不改变提取结果；相同标识但数值矛盾则拒绝。
- 入庙互容的闭环成分与传统定位双环使用相同 `synonym_group`，但接纳的其他依据仍保留。
- 风筝内的大三角、小三角、楔形保留，以 `contains` 和 `shared_with` 记录，不累加任何分数。
- 落角宫与合轴分别保留，通过 `correlation_group` 关联。
- 合MC/冲IC等对轴表达归成一个轴线接触，`expressions` 保留两种表述。始终用基础计算的真实轴点，绝不拿整宫十宫宫头替代MC。

`source_refs` 是以完整返回值为根的来源字段路径；数组来源通过记录中的行星、相位ID、构型ID或宫位匹配。`depends_on` 中的 `lon:*`、`a:*` 对应源图谱事实及相位标识；其他语义标识指提取证据或具体轴点/宫位事实。不同证据族也不声称统计独立。

## 相位口径和可用性

互容分别记录接纳依据、上游 `has_aspect/aspect`、从上游几何重建的orb，以及 `current_view` 是否包含和orb。不将“当前视图无相位”改写成“上游从未成相”，也不把有相位解释成更好。单向接纳保留源引擎记录与口径。

元素/模式默认十二点（十星＋ASC＋MC），逐项列出点集；缺轴点时保留十星计数，标记缺失点与部分覆盖。半球/象限依赖宫位，各宫制单独标可用性；整宫的半球是宫位编号分组，不是精确地平几何。

现有七种构型为大三角、小三角、楔形、T三角、风筝、神秘矩形、大十字。Yod不在本版，明确列入 `unsupported`。高纬度源图谱缺宫位时，不伪造命主、轴点和宫位结论，定位与行星相位仍可用。

## 验证

### 角色索引与分维核查（角色v2／关系v3）

本轮替换尚未发布的v1实验规则。顶层字段名保留，但嵌套版本分别升级为 `natal-priority-policy-v2`、`natal-resource-policy-v3`。本地消费者应读取版本字段迁移；`tier`、`domains`、`largest_basin_terminal_ids` 以及候选的统一 `status` 已删除，不再输出高低等级。

`priority_decisions` 是角色索引，覆盖全部十星与所有终端，包含：终端成员、主要入口、其他行星的定位星、日月、命主／可选MC主、合轴／轴点相位、构型角色、宫主、紧密相位参与者，以及既有资源路线的连接对象。每条角色附对象、细节和可解析来源。它不按最大汇入过滤，不累计角色数排序；画像是否入选与角色是否存在分别记录。

`resource_decisions` 对每个事项的候选分开提供三个维度：

| 维度 | 输出与边界 |
| --- | --- |
| `relationship` | 已计算成立的定位、互容、定向尊贵、五种主要相位与共同构型路线，逐端点保留orb与当前／上游相位口径；记录端点覆盖，不能因候选状态不佳而取消关系 |
| `counterpart_state` | 尊贵多标签、运行、日光、两制宫位、掌管宫位和刑冲；每一维单独标可用性，不合成好坏分数。刑冲区分涉及本事项当事星或位于盘内其他位置 |
| `applicability` | 说明这条关系为当前事项提供哪种关联背景；不判定已解决事项 |

适用性规则是本项目明示的组织策略：

- 本体状态：区分定位／互容背景（`governance_or_reception_context`）、只有相位背景（`aspect_context_only`）以及仅当事星连接。不要求候选“无缺点”才保留这些背景。
- 刑冲：区分连接两个端点、一个端点，或者只有定位／互容关系。此处相位连接包含当前档内全部五种主要相位，具体角度和orb仍保留。尊贵关系的host/guest方向及共同构型连接另列，不冒充直接相位。只有这两类连接时标记 `structural_connection_only`。共同连接不自动定义新构型。
- 逆行、日光与宫位关联：只标背景连接（`background_connection_only`），不能改写本命运行、日光或宫位事实。
- 未声明的事项类型返回 `no_topic_rule`，不猜测结论。

外行星缺少古典尊贵时只将状态维度标为未定义；已成立相位仍成立。候选逆行、落8宫、掌管12宫或另有刑冲，仅保留为状态事实，不降低关系与适用性的等级，因为这两维不设好坏等级。缺少刑冲另一端画像时，适用性覆盖标记部分，而不是推翻已知端点关系。

`effective_remedy=null`、`ability_to_resolve_issue=not_established`：当前输出的是可复算的关系、状态和事项关联，不承诺“最佳用药”。无外部候选只表示未命中现有连接规则。v1的支持／有条件／依据不足统计仅保留在历史验收记录，不代表当前结果。


### 接纳事实与算法边界（2026-10-22）

`reception_facts` 复用 `classical_engine` 尊贵表，遍历古典七星的有向关系。`host` 是在 `guest` 黄经处拥有尊贵的星；每项依据单独列出，庙旺属于major，三分界面属于minor。`meets_dignity_threshold` 沿用当前引擎“至少一项major或两项minor”的项目口径，不声称各流派统一。反向关系以 `reverse_id` 链接；两向均达门槛才标 `mutual_dignity_threshold`。低于门槛的已知依据仍留在事实表，但不因此进入候选路线。

星座几何与度数几何分列：`sign_geometry` 给出星座距离、同座、托勒密角度及1/5座间隔的aversion；`degree_geometry` 给出实际夹角及距五种精确角度的偏差；`current_view` 只记录所选上游相位档是否包含该边。例如星座三分可以不在当前三分容许度内，跨星座边界的度数六合也可以与星座厌恶同时出现。这里不把两种口径混成“互容质量”。

`phase` 由 `aspect_dynamics` 提供：出生时刻的黄经差及相对速度决定 `applying`、`separating`、`relative_stationary` 或 `exact`。无当前度数相位的关系标 `not_applicable`；纯结构函数没有动态输入或星历覆盖不足时为 `unknown`。不把逆行本身等同于入相或出相。

`policy_evaluation` 是项目公开定义的条件组合，不标为某位作者的原始公式：仅尊贵门槛；尊贵且星座成相；尊贵且当前度数成相；尊贵、度数成相且正在入相。每条输出 `checks`、`required`、`failed`、`unknown`、`meets`，未知保留null，精确态与入相态分开。切换规则不会删除原始关系、自身状态或定位终端。

向后搜索复用星历接口 `transit_utils.body_position` 和已有相位扫描二分求根器：地心、热带、视黄经及其速度，强制检查Swiss文件模式，不以Moshier回退冒充。每条已在所选档内的相位沿出生时最接近的有向分支，查找窗口内第一个精确点；3小时网格再取中点，分段检查相对速度驻点，根的数值时间容差0.05秒。这是求根容差，不是对天文观测精度的承诺。实现依照 [Swiss Ephemeris位置和速度接口](https://www.astro.com/swisseph/swephprg.htm)。

`search` 区分出生时精确、窗口内找到、窗口内未找到及星历不可用。此前的个体停滞、相对速度转向和换座单独记录；未找到不等于永远不能形成，出相以后仍可能在窗口内再次形成。同一对只返回第一命中；查询重复命中请使用通用扫描工具。换座或转向不自动判成“互容失败”。本版不判断第三颗星阻断、光线转移、事项成败或有效用药。
