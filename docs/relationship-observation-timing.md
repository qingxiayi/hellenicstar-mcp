# 关系观察时间层 v0.14

这是`calculate_relationship_observation`的可选层，默认关闭。它回答“在指定时间，哪些位置被行运或次限触碰，这些位置与双方本命接触怎样重合”，不预测相遇、关系进展或结局。微信小程序及旧关系工具不变。

## 来源与工程边界

依据原书第六章 *Transits and Progressions in Synastry*：开篇提出查看相遇时的行运／次限与本命区域；Charles／Diana段落说明日期不确切时用月中示意，但快速行星不能因此视为准确；Tom／Katie段落比较时间层与伴侣触及的本命区域，并查看行运对次限、伴侣本命对次限；章末提出比较两张次限盘及关系期间行运与跨盘相位。附件页序126、129、138、142–143仅作辅助定位。

原书未在这些段落给出统一时间层容许度。本层必须显式配置行运与次限的相位窗口，**不继承静态关系层的10°**。数值、时间采样、有限结构引用、去重与停止规则均标工程口径。原书的象征性“伴侣承载某种行运性质”没有自动匹配；本层仅比较可计算的几何位置和既有结构。

## 调用

在原有两份完整出生资料及关系场景之外加入：

```json
{
  "include_timing": true,
  "timing": {
    "at": "2020-06-01T15:30:00+08:00",
    "transit_orbs_degrees": {"0": 1, "60": 1, "90": 1, "120": 1, "180": 1},
    "progression_orbs_degrees": {"0": 1, "60": 1, "90": 1, "120": 1, "180": 1},
    "angle_progression_method": "naibod",
    "include_progressed_synastry": true
  }
}
```

示例中的1°仅是调用配置，不是产品默认或作者规则。两个orb字典均须非空，支持0/30/45/60/90/120/135/150/180，未列角度不独立计算；轴线互补端点沿用等价表示。阈值须有限且处于0–10接口范围，包含轴线补角的相位窗口不得重叠。静态本命结构仍用原静态配置，不能用时间层六合阈值偷偷启用本命六合格局。

时间输入四选一：

| 输入 | 行为与限制 |
|---|---|
| `event: "childbirth"` | 从明确角色为child一方的完整出生资料解析UTC时刻；必须选择family场景及parent/child角色 |
| `at` | 带明确UTC offset的ISO时间；不接受缺时区的时间或仅日期 |
| `date` | `YYYY-MM-DD`，当天12:00 UTC示意；不声称知道事件时刻 |
| `month` | `YYYY-MM`，月中15日12:00 UTC示意 |
| `month`加`month_part` | early／middle／late，工程映射为1–10／11–20／21日至月底，分别取5／15／25日12:00 UTC示意 |

`date`、`month`及`month_part`输入均排除日月水金火行运，保留实际输入精度及日历范围。UTC是参考计算钟表，不代表实际相遇地或当地中午。日期精度本身不会自动开启区间扫描；单个快照不能代表整段日期。需要区间结果时另传下面的窗口参数；非精确事件时间的快速行星排除规则仍生效。出生资料仍要求完整，事件日期近似不会放宽出生输入要求。

时间须不早于任何一方出生，且处于现有次限引擎支持的0–120岁内。v0.14仅支持synastry模式。四轴推进默认复用Naibod，可显式切换solar_arc_in_ra；它们是现有引擎方法，不冒称作者指定算法。

## 可选区间扫描（v0.12）

在同一个`timing`对象中同时提供`window_start`和`window_end`，如`2022-09-01T00:00:00Z`与`2022-09-11T00:00:00Z`。两者必须含UTC offset；窗口至少1秒、至多31天，选定快照时间须在窗口内。起点包含，终点不包含；输出统一UTC。这是明确的计算范围，不是实际事件时刻的推断。

`timing_observations.window_scan`返回：

- `contacts`：所有启用的点对与相位在窗口内的接触序列，不只扫描快照已有接触。每条保留端点、角度、阈值及本命／伴侣／结构引用。
- 每条的`exact_events`记录数值求得的精确接触时刻与残差；`windows`记录处于容许度内的区间。`start_clipped`／`end_clipped`表示已在查询边界内成立，不能将查询边界当作真实进入／离开时间。
- `constant_exact_intervals`单列持续精确的退化情况；`threshold_touch_times_utc`保留容许度边界接触时刻，包括只切触边界而没有正时长区间的情况。
- `synastry_endpoint_overlaps`要求同一行运行星触碰原跨盘相位两端，且两个容许度区间确有正时长交集；不把窗口内分别发生当作同时发生。
- `counts`分别统计唯一接触序列、精确事件和容许度区间，三者不可相加，也不加到静态接触数或强度评分中。

这是有界数值搜索：6小时网格含中点检查，使用相对速度转向分段，复用现有扫描器的二分求根；角度容差1e-7度、时间容差0.05秒。相对速度采用前后0.001天有限差分并限制在查询范围内。网格、最大跨度和容差均是工程决定，不是作者提供的阈值；这不是对任意高频振荡函数的严格区间证明。逆行重复接触保留独立过境，边界重复事件去重。两张次限盘间接触可按原参数关闭。

## 输出

`timing_observations`包含：

- `sources`：选定UTC／JD、公共行运位置、双方次限位置与推进JD、实际推进方法。行运没有A/B人格主体；没有计算事件盘四轴。指定日期／时间仍沿用时间层的真交点适配；亲子出生事件使用平均交点，与经核验的本命来源一致。`node_conventions`明确记录本命、行运和次限各自口径，不能把真／平均交点视为同一个位置。旧次限工具不变。
- `contacts`：行运→双方本命／次限；双方次限分别→自己和对方本命；可选次限A↔次限B。每个几何接触存一次，两端所属人、盘类型、位置引用、真实orb、调用阈值与轴线等价端点均保留。入出相及紧密展示阈值未定义，不填充推断。
- `natal_point_entries`：每个被时间层直接触碰的本命点，关联对方实际接触及一跳本命相位。没有对方直接接触的时间层入口也保留。
- `natal_complex_entries`：沿用原有限结构，分别列核心与附属背景成员的时间层／伴侣接触引用。只有核心确实被两类接触触及时，`time_and_partner_both_touch_core`为true；不宣称全体成员都直接触发。
- `transits_to_synastry_endpoints`：已有静态跨盘相位的两个端点，各自有哪些行运接触。端点两侧都有接触不意味着同一颗行运行星同时触碰两侧，须查看各条引用。

`counts.unique_timing_contacts`仅计时间层几何，不能与本命／跨盘／结构视图计数相加。开启时间层不改变静态`contacts`、`observation_paths`、`activation_clusters`、落宫或原`counts`。所有引用指向完整结果；摘要截断时应按presentation提示取完整数据。

## 验证与未覆盖项

服务器先用已有几何构建关联，再对时间源重算并检查完整输出；`verify_calculation_claims`继续支持新字段的计算引用复算。验证不证明占星解释或当事人经历。

未实现：超过31天的单次长时段搜索、语义Carrier匹配。两张次限盘自身的新格局检测未加入；本轮核对未找到它是原书必须自动计算的明确要求，不再把它列为已确认的原书缺口。现有复杂结构引用指向本命。

本版本只做本地实现与验证，不代表部署。旧引用须按新规则版本重新计算。

发布验证使用合成输入和随源码提供的边界测试；私人案例不随源码分发。

## v0.13：子女出生时的父母观察入口

输入示例（仍须另外提供双方完整出生资料）：

```json
{
  "relationship_type": "family",
  "relationship_context": {"roles": {"a": "parent", "b": "child"}},
  "include_timing": true,
  "timing": {
    "event": "childbirth",
    "transit_orbs_degrees": {"0": 1, "90": 1, "180": 1},
    "progression_orbs_degrees": {"0": 1, "90": 1, "180": 1}
  }
}
```

角色可互换；family也可作为明确选择的附加场景。`event`不能与`at`、`date`、`month`同时提供。系统复用出生地点／时区／夏令时fold解析，拒绝缺失资料、未声明角色、子女早于或同时于父母出生等输入；不靠年龄或性别猜角色。不推断生育、怀孕、养育或心理经历。

原书第七章Family总结指出：“a child’s chart shows the transits a parent was undergoing at the time of birth”，Fisher／Reynolds案例进一步列举母亲本命被触碰的位置。概念记为JG_EXPLICIT；自动取时、去重和数据结构是ENGINE_DERIVED。所示1°仍是示例配置，不是作者默认。

`timing_observations.childbirth_observation`是时间接触的引用视图：只列行运→已声明父母本命，附子女对应本命点、父母本命点、一跳上下文入口与有限结构引用。静态策略也有相同相位时，附原`contacts`引用；时间层启用六合而静态未启用等情况会明确标无对应静态接触，不能伪造引用。同一几何既作子女本命又作出生行运，不增加独立证据或静态计数。子女四轴不当成行运行星。

出生事件具有具体时刻，所以保留快速行运；子女在该时刻的次限年龄为0。若另开窗口，仍受所有人的出生时间与31天限制，不能扫描到子女出生前后却忽略次限范围错误。双亲分别与子女计算；不会由一份双人请求补出未输入的另一位父母。

**交点更正：** 运行核对确认旧本命引擎虽将字段命名为`true_north_lunar_node`，实际主路径调用的是`swe.MEAN_NODE`。v0.13将独立观察层本命标注改为mean，并按出生UTC重新核验平均交点；数值保持原样。亲子事件使用mean保持几何一致；此前指定时间的true行运／次限不改动，混合口径显式披露。这不代表已修复共享引擎字段名或其他工具。详见v0.13验收（内部历史验证记录，不随源码分发）。

## v0.14：本命与次限关系盘的同口径对照

当`include_timing=true`且`timing.include_progressed_synastry=true`时，新增`timing_observations.progressed_synastry_comparison`。设为false则明确不计算，不新增必填参数。

依据第六章结尾：作者建议比较两张次限盘，观察本命关系盘中原有的刑相等是否仍在，或是否形成其他相位。定位短语为“Planets that were square in the natal synastry may not be any longer”。这是比较两个阶段的跨盘相位，并不能直接推出作者要求扫描每张次限盘内部全部新格局。后一项保留为未实现的可选工程扩展，不作为原书必补项。

比较使用**同一套显式`progression_orbs_degrees`**：本命位置重新按此策略判相，次限侧引用已计算的次限互比相位。原静态10°结果及其排序不改变；不能用静态10°与次限1°直接对比存在／缺失。`natal_comparison_contacts`是已有本命位置的同口径复核，不能加作新证据。

`entries`每个规范点对最多一条，列出双方点位引用、可选的本命比较相位引用／次限相位引用，以及同点对的原静态接触引用。没有相位的一侧省略相位引用字段，仍保留位置引用。原静态引用仅提供背景，不作为变化判定的基线。

| `state` | 仅表示当前比较口径下 |
|---|---|
| `same_aspect` | 本命与指定次限时刻均有同一种相位 |
| `different_aspect` | 两边均有相位，但种类不同 |
| `natal_only` | 本命基线成立，指定次限时刻不在启用的容许度内 |
| `progressed_only` | 指定次限时刻成立，本命基线不在启用的容许度内 |
| `not_comparable_node_conventions` | 涉及交点且本命／次限口径不同，不判作相位变化 |

两边均无启用相位的点对不输出。轴线等价端点共用一条。交点口径仍遵循v0.13：普通指定时间为平均本命／真次限，涉及交点的条目不可直接比较；亲子事件全部为mean，可以进行同口径比较。不会为了比较更换本命坐标。

这只是指定快照的对照，不断言“第一次出现”“永久消失”、持续时间或关系变好／变坏。窗口扫描不会把快照对照推广为整个窗口结论。各状态计数不是强度权重，不与原接触数相加。几何来源和引用由原验证流程复算；见v0.14验收（内部历史验证记录，不随源码分发）。
