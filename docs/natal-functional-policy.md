# 功能匹配规则账本：functional-v1

这是本项目的实验性解释策略。来源是对用户提供的报告架构的分析，不是已知原引擎源码、某个已核实的学派公式或心理学模型。报告是研究案例，不把其个人数据、终端成员或结论写入规则。公开代码与样例只包含规则和合成输入。

## 分清三种输出

| 问题 | 当前来源 | 边界 |
| --- | --- | --- |
| 哪些结构汇聚、如何连接 | 结构图谱和角色索引 | 可复算结构事实，不等于心理重要性 |
| 资源可能如何参与具体问题 | 功能匹配规则与当前实际路线 | 条件性象征假设，需要实际经历核对 |
| 哪条路径先核查 | 候选自身假设的依赖图 | 审阅顺序，不等于必须先解决某颗星 |

## 从报告思想到可执行规则

| 报告表现出的原则 | 本次可执行规则 | 没有据此声称什么 |
| --- | --- | --- |
| 四点合看 | 每个假设引用完整画像，保留状态、宫位、全档相位和定位星；机制暂覆盖本体状态与定位、刑冲功能协调 | 未声称所有四点已被完整综合成情境判断 |
| 病在运作受阻，而非某颗星本身 | 把同星事实归成待核对问题，输出机制与替代解释 | 不能由出生数据证明实际存在某种行为 |
| 资源要对准问题 | 机制声明所需操作；候选须同时有直接关系和功能匹配 | 三分／六合不是自动有效，定位星也不保证有帮助 |
| 药本身可能有病 | 资源状态照常保留，补核查条件；不自动否定候选 | 不以刑冲、逆行或落8宫一刀切 |
| 好相位也会放大旧模式 | 每项操作同时附反效果和观察问题 | 不能预知实际走哪一条分支 |
| 顺序受前提影响 | 给采用某候选的路线建立条件性审阅依赖；循环共同审阅 | 不从拓扑推出唯一人生顺序 |
| 独立线索重复汇聚 | 来源、同义及共享事实保留，不计票；同一刑冲两端共用ID | 不虚构独立证据数量或总分 |

## 规则组成

实现中的 `OPERATIONS` 给十颗星各定义一个象征功能、可尝试的操作、观察问题和反效果。`NEEDS` 只用于本体状态与定位星机制的基础匹配；`PRESSURES` 用于刑冲中另一端可能牵动的协调问题。它们都是**可检查、可修订的项目规则**，不冒充计算事实。完整取值在源码及每次开启策略后的 `registry` 中返回。

机制：

- `condition_through_dispositor`：失势或落陷且定位星不是自身时，核对自身功能是否过度依赖定位星代表的要求，同时保留“定位关系形成稳定承接”的替代解释。
- `hard_aspect_function_coordination`：当前相位档内的刑冲，分别提出双方功能协调的问题。另一端不同，所需操作不同；不能只按目标星固定配资源。

匹配：

- 实际路线来自原 `resource_review`，不复制守护、尊贵或星历算法。
- 未命中功能表的路线保留在 `route_audit`；不表示永远不可用。
- 互容在当前相位档无相位时，增加显式协调条件，不修改上游是否成相的事实。
- 候选自身刑冲触发核对条件；其自身若有机制假设，引用该假设作为条件性审阅依赖。不根据候选状态删掉连接。
- 所有尝试先核对问题是否实际存在。不符合时不采用该假设，而非逼迫现实适配星盘。

## 已知差异与未完成部分

- 没有还原原报告的精确评分公式；目前也没有证据证明原报告存在这样的公式。
- 不自动给资源排第一、第二、第三；不预设任何特定终端或“药”。
- 宫位、宫主与落座还作为完整背景提供，尚未全部进入细化情境规则。
- 没有声称三分／六合一定有利；反效果目前是操作级候选分支，不是对真实结果的预测。
- 月土、水火等只是可能输入中出现的关系；不要求每个盘都有这些关系。
- 三分尊贵仍沿用既有昼夜主口径，并列出其他角色；未以案例中的措辞修改古典状态。
- 文献注册为 `unregistered`。测试只能证明执行一致、来源存在和不同输入能够处理，不能证明象征模型的真实性或有效性。

## 验证方式

反例测试包括：同一目标、相同连接、不同刑冲另一端时功能匹配改变；有功能但无路线不输出；有路线但无规则明确留空；候选有刑冲仍可匹配；缺宫位保留未知；循环依赖不强行指定首位；开启策略不改变任何原有计算／角色／资源三维字段。出生标签和输入排序不能影响结果。

部署状态以验收记录为准，文档和源码更新不代表公共服务已经更新。
